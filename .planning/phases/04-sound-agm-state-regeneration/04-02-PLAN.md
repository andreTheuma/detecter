# Plan 04-02: Singleton AGM Deduction and Withholding

<objective>
Replace the current list-as-state recovery bug with an explicit deterministic recovery contract. Missing-event handling must infer one system state and prove one monitoring consequence across all compatible missing events. Exact event recovery is optional metadata, while ambiguous, impossible, conflicting, or unproven cases must withhold rather than emit a verdict.
</objective>

<tasks>

1. **Generate singleton helper logic**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Add `generate_resolve_singleton_state_function/0`, which emits helper logic equivalent to:

   ```erlang
   resolve_singleton_state([State]) -> {ok, State};
   resolve_singleton_state([]) -> {withhold, impossible_recovery};
   resolve_singleton_state(_) -> {withhold, ambiguous_state}.
   ```

   - Add the generator to `agm_generation/0` before `generate_handle_missing_event_function/0`, because the generated handler will call this runtime helper.

2. **Generate candidate-event descriptor collection**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Generate `candidate_event_specs/2` so it searches transition rows from the known pre-missing state `X0` to the inferred post-missing state `X1`.
   - Preserve every distinct literal or symbolic descriptor for `X0 -> X1`.
   - Treat an empty descriptor set as impossible recovery.
   - Do not withhold merely because several events or a symbolic range remain possible.

3. **Fix `handle_missing_event/1` state inference**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Treat the state stored in ETS when the missing marker arrives as `X0`, the known source state immediately before the missing event.
   - Compute candidate set `S_X1` as the intersection of states reachable from `X0` and states compatible with the next observed event.
   - Require `S_X1` to contain exactly one state before continuing.
   - Collect compatible missing-event descriptors from `X0 -> X1`, never from a candidate state list.
   - Leave the monitor at scalar state `X1`; replay of the already-observed next event remains Phase 5 work.

4. **Return recovery or withholding explicitly**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - On success, update ETS to set `previous_state = X0` and `current_state = X1`, then return:

   ```erlang
   {ok, #{
       source_state => X0,
       inferred_state => X1,
       event_specs => EventSpecs
   }}
   ```

   - Keep the contract consistent throughout generated monitor states and tests.

5. **Resolve monitoring consequences before continuing**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Reduce every candidate event descriptor through the current generated monitor state.
   - Compare complete consequence signatures: terminal verdict, or continuation function together with all bound argument values.
   - Continue only when the resulting signature set is a singleton.
   - Record `{known, Event}` only for one literal descriptor; otherwise record exact-event metadata as `unknown`.
   - Ensure `{withhold, Reason}` never calls `rejection/1`.

6. **Prove supported symbolic consequences without enumeration**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Support event-independent unguarded continuations and complementary equality/inequality guards over known descriptor domains.
   - Return `unproven_consequence` for unsupported symbolic guards or domains.
   - Return `ambiguous_consequence` when a symbolic domain admits more than one proven consequence.

</tasks>
