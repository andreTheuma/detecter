# Plan 04-02: Singleton AGM Deduction and Withholding

<objective>
Replace the current list-as-state recovery bug with an explicit deterministic recovery contract. Missing-event handling must recover only singleton state and singleton concrete event cases, and must withhold rather than reject all ambiguous, impossible, or symbolic cases.
</objective>

<tasks>

1. **Generate singleton helper logic**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Add `generate_resolve_singleton_state_function/0`, which emits helper logic equivalent to:

   ```erlang
   resolve_singleton_state([State]) -> {ok, State};
   resolve_singleton_state([]) -> {withhold, impossible_recovery};
   resolve_singleton_state(_) -> {withhold, ambiguous_state}.
   ```

   - Add the generator to `agm_generation/0` before `generate_handle_missing_event_function/0`, because the generated handler will call this runtime helper.

2. **Generate concrete event deduction**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Add or replace generated event lookup so it searches transition rows from the known pre-missing state `X0` to the inferred post-missing state `X1`.
   - Return `{ok, Event}` only when exactly one matching transition has a literal event descriptor, unwrapping `{literal, Event}` to the concrete event.
   - Return `{withhold, ambiguous_event}` for multiple matching literal event candidates.
   - Return `{withhold, symbolic_event}` for matching symbolic/ranged descriptors.
   - Return `{withhold, impossible_recovery}` when no transition exists.

3. **Fix `handle_missing_event/1` state inference**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Treat the state stored in ETS when the missing marker arrives as `X0`, the known source state immediately before the missing event.
   - Compute candidate set `S_X1` as the intersection of states reachable from `X0` and states compatible with the next observed event.
   - Require `S_X1` to contain exactly one state before continuing.
   - Deduce the missing event from `X0 -> X1`, never from a candidate list.
   - Leave the monitor at `X1` so the already-observed next event can be retraced and processed normally in Phase 5.

4. **Return recovery or withholding explicitly**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - On success, update ETS to set `previous_state = X0` and `current_state = X1`, then return:

   ```erlang
   {ok, #{source_state => X0, inferred_state => X1, event => Event}}
   ```

   - If map construction becomes awkward in `erl_syntax`, use a tuple instead:

   ```erlang
   {ok, X0, X1, Event}
   ```

   - Keep the contract consistent throughout tests.

5. **Stop mapping recovery failure to rejection**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Update generated missing-event case expressions so `{withhold, Reason}` does not call `rejection/1`.
   - Returning `{withhold, Reason}` or `withhold` from the generated function is acceptable for Phase 4 as long as no verdict is sent.
   - Keep event replay/verdict equivalence work deferred to Phase 5.

</tasks>
