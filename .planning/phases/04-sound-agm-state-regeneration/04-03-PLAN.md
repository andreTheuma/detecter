# Plan 04-03: AGM Monitoring-Consequence Regression Tests

<objective>
Add generated-module regression tests proving that AGM requires singleton state inference and a deterministic monitoring consequence, while treating exact missing-event recovery as optional.
</objective>

<tasks>

1. **Create generated AGM recovery EUnit module**
   - File: `detecter/test/regeneration/generated_agm_recovery_test.erl`
   - Generate monitor modules into temporary directories using `maxhml_eval:compile/2`.
   - Compile generated modules with `export_all` for tests so unexported generated AGM helpers can be called directly.
   - Clean up temp directories recursively.

2. **Test unique concrete event and deterministic consequence**
   - Use the token-system spec where `LastKnownState = s1`, missing event is `0`, next observed event is a concrete value accepted from `s2`.
   - Seed `sus_state` with the last known state.
   - Send the expected next trace event to the test process mailbox before calling generated `handle_missing_event/1`.
   - Assert `{ok, Recovery}`, a deterministic monitor consequence, and optional event metadata `{known, 0}`.

3. **Test ambiguous state recovery**
   - Use a temporary system-info spec where the intersection for `S_X1` has multiple states.
   - Assert `{withhold, ambiguous_state}` or the agreed equivalent reason.

4. **Test multiple concrete events with the same consequence**
   - Use a temporary system-info spec with duplicate `Src -> Dst` rows carrying different literal events.
   - Use a generated monitor state whose pattern, guard, continuation, and resulting bound values are identical for every candidate.
   - Assert that monitoring proceeds with one consequence while exact event metadata is `unknown`.

5. **Test multiple concrete events with conflicting consequences**
   - Use duplicate `Src -> Dst` rows whose events select different generated monitor branches, verdicts, or bound values.
   - Assert `{withhold, ambiguous_consequence}`.

6. **Test impossible recovery**
   - Use a temporary system-info spec or current-state/next-event combination where no compatible `S_X1` exists.
   - Assert `{withhold, impossible_recovery}`.

7. **Test a uniformly reducible symbolic range**
   - Use a symbolic/ranged descriptor, such as `N`, that is wholly contained in one generated monitor branch.
   - Assert that monitoring proceeds with one consequence and exact event metadata is `unknown`.

8. **Test an unproven or conflicting symbolic range**
   - Use a symbolic descriptor that crosses monitor guard boundaries, or an unsupported guard for which uniformity cannot be proven.
   - Assert `{withhold, unproven_consequence}` or `{withhold, ambiguous_consequence}` according to the implemented analysis result.

9. **Wire test into default target**
   - File: `detecter/Makefile`
   - Add `generated_agm_recovery_test` to `make test` after `generated_monitor_smoke_test`.

</tasks>
