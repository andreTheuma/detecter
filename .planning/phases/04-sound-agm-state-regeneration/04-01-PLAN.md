# Plan 04-01: Preserve Transition Multiplicity

<objective>
Change generated system-information data so AGM recovery can observe duplicate state-pair transitions and retain event descriptors. This is a representation-only step: generated monitors should still compile, and existing helper behavior should remain equivalent where multiplicity does not matter.
</objective>

<tasks>

1. **Introduce event descriptors in transition generation**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Add generator helpers that convert parsed `sys_info_parser` event tuples into both:
     - an `EventSpec` AST, such as `{literal, 0}` or `{symbolic, natural_integer}`
     - the existing predicate function AST
   - Preserve the current predicate semantics for integers, atoms, `N`, `Z`, `R`, and set-minus guards.

2. **Emit `init_transitions/0` as a list**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Replace the generated map expression with a list of transition tuples:

   ```erlang
   [{Src, Dst, EventSpec, ConditionFun}]
   ```

   - Do not collapse duplicate `{Src, Dst}` transitions.

3. **Update generated helper folds**
   - File: `detecter/src/synthesis/maxhml_eval.erl`
   - Update `get_system_states/0`, `reachable_state/2`, `reachable_states_from_state/1`, `preceeding_states_from_state/1`, `preceeding_states_from_event/1`, and `validate_state_transition/2` generation to fold over the transition list instead of `maps:to_list/1`.
   - Preserve existing helper names, including `preceeding_*`, to keep this phase focused.

4. **Maintain generated compile coverage**
   - File: `detecter/test/regeneration/generated_monitor_smoke_test.erl`
   - Keep the Phase 3 compile matrix passing for `prop_no_leak`, `prop_no_failure`, and `prop_correct_start`.
   - Add a source assertion only if it is low-noise, such as checking generated source no longer contains `maps:to_list(StateTransitionTable)` inside AGM helpers after the representation switch.

</tasks>
