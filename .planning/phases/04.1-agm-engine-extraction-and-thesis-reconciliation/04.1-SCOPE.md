# Phase 4.1 Insertion Scope

**Status:** Inserted, not yet planned
**Depends on:** Phase 4, including permanent Plan 04-03 characterization tests
**Blocks:** Phase 5 irrevocability and verdict-semantics work

## Purpose

Extract AGM responsibilities from `maxhml_eval.erl` without changing the soundness contract established in Phase 4. The refactor must leave clear boundaries between:

1. maxHML semantic traversal and monitor orchestration;
2. property-specific AGM Erlang AST generation; and
3. reusable AGM runtime inference and consequence aggregation.

The runtime engine must remain independent of verdict side effects. Generated monitor states retain responsibility for supplying property-specific reduction behavior and invoking a verdict or continuation only after the engine proves one monitoring consequence.

## Locked Safety Gates

- Do not begin behavioral extraction before Plan 04-03 regression tests characterize singleton recovery, transition multiplicity, literal consequences, symbolic consequences, optional exact recovery, and all withholding outcomes.
- Preserve complete consequence identity, including bound values.
- Do not introduce probabilistic or approximate recovery.
- Make any generated-monitor runtime dependency explicit.
- Run the full default test target and focused generated-module tests before and after each extraction boundary.
- Do not mark this phase complete while thesis text describes the pre-refactor architecture.
